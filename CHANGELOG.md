# GutsKernel Changelog

Add each release at the top of this file, newest first. Use a numeric version
heading in the format `## vX.Y.Z - YYYY-MM-DD`, followed by bullet points
describing user-visible changes. The release workflow includes at most the five
newest version sections in the GitHub Release description.

Example format (replace the version, date, and example notes for each release):

```markdown
## vX.Y.Z - YYYY-MM-DD

- Added support for a new kernel feature.
- Fixed a build or device compatibility issue.
- Updated the included kernel patches.
```
